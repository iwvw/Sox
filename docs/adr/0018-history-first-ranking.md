# ADR-0018. 排序：历史命中提升为最高层（修订 ADR-0013）

日期：2026-10-01
状态：Accepted

## 背景

ADR-0013 把历史行为分降为「同起点档内的加权项」：只有两个结果的匹配**起始位置相同**时，行为分才决定先后。后果是：一个你经常打开、但匹配起点靠后的文件（如历史里的 `ApeRadar.exe`，输入 `a` 时起点不在 0），**永远排不过**一个匹配起点为 0 的新文件。用户实测反馈「搜过的、打开过的条目不会在输入第一个字母后立刻排到最前」。

对照上游 Lertaro（ADR-0010 的参考实现）：历史/收藏是**最顶层 tier（curated）**，无条件压过所有非 curated 结果；组内再按历史顺序 / 文本匹配排序。见 `E:\Code\Lertaro\App\ViewModels\Search\Mapping\RankedCandidateOrdering.cs`：

```
IsCurated 降序 → Priority 升序 → TypeRank → Match.Start → Match.Weight 降序 → Match.Tier → 路径长度 → 路径
```

## 决策

把历史命中提升为最高层，排序阶梯改为：

```
1. 是否在历史里（curated）           ← 命中过历史的排最前，无条件
2. 行为分（越大越前）                ← 同层内：频次 + 时间衰减 - 惩罚
3. RankSortKey 完整字典序            ← 相关度：start(8) > weight(16) > tier(8) > span
4. 路径长度 → 盘符 → 路径
```

即：**在历史里的 > 不在历史里的；同在历史里的按行为分；行为分相同再按相关度。**

与 ADR-0013 的差异：
- ADR-0013：`start` 是第一主键，行为分只在同 `start` 档内起作用（历史不能越权）。
- 本 ADR：curated（是否在历史里）是第一主键，历史可以越权压过相关度更高的新结果。

保留 ADR-0013 的合理部分：
- 非历史结果之间，仍是 `RankSortKey` 字典序，即 `start` 优先 —— 避免「短名系统性占优」。
- 行为分公式不变（`HistoryRankWeights`：频次 `log2(1+count)×300`，时间衰减 1h:+800 / 24h:+400 / 7d:+200，惩罚 `passovers×200` 上限 3）。
- 惩罚机制不变：越过前 N 条选中第 N+1 条时，被越过项各 +1。

## 安全性说明

进入排序的结果都来自索引搜索，**已经匹配过当前输入**（不是凭空造行）。因此把「在历史里」设为最高层，只是把「你已经用过、且这次也匹配」的条目提上来，不会引入与输入无关的行。这与 Lertaro 的 curated tier 语义一致。

（Lertaro 另有一路「用当前输入去匹配历史记录时的关键字」的召回，可以命中**名字不含该词**的历史项；Sox 暂不实现，见下。）

## 后果

- 输入第一个字母时，搜过/打开过的条目立刻置顶，行为符合 Listary 直觉。
- 极端的陈旧历史（很久以前只开过一次）也会压过完美新匹配；这是「历史优先」的固有代价，与 Lertaro 一致。若后续觉得过于激进，可在行为分里加大时间衰减的权重来缓解。
- 行为数据仍与索引分离，重建索引不清历史。

## 未做（后续可选）

- **关键字召回**：用当前输入模糊匹配历史条目记录的关键字，命中即注入候选（可命中名字不含该词的历史项）。需要把历史条目还原成结果行并并入候选集，是独立的一块。
- 收藏：Sox 目前没有独立的收藏 tier（`FavoriteItemSetting` 仅在动作菜单里「固定到收藏」写入，未参与排序）。若要做，应与历史同级或更高。
