# ADR-0006. 排序引擎：相关度硬门槛 + 行为加权

日期：2026-09-29
状态：Accepted

## 背景

Listary 的「智能感」来自历史学习排序。需要越用越准，且不能把低相关项顶上来（智能而不是神经）。

## 决策

- 双阶段排序：
  1. 过滤：相关度 `rel_match < 阈值` 直接丢弃（历史分不能越权）
  2. 加权：
     ```
     final = rel_match × 10000
           + log2(1 + hit_count) × 300
           + recency_bonus        ← 1h:+800 / 24h:+400 / 7d:+200
           + fixed × 5000
           - penalty × 200
           + context_bonus        ← 当前目录 +1000
     ```
- 输入越短行为分权重越大，输入越长相关度权重越大
- 学习打点：打开即 hit_count++ / last_used；用户选了第 N 项则前 N-1 项各 penalty+1
- 行为数据 30 秒合并批量落盘（防 SSD 磨损），存 `%APPDATA%` JSON / LiteDB
- 冷启动：rel_match + 目录深度 + 常用目录（桌面/下载/用户目录）

## 后果

- 获得「越用越准」体验；公式需随使用反馈长期调参
- 行为数据与索引分离存储，索引重建不清历史
- 上下文信号（活动窗口目录）P1 阶段先占位
